# Haajar v0.9.0-beta.3

Third closed beta release of Haajar.

## Changes since beta.2

- Repaired operational-group access so organisers can join new subgroups, assign organisers, and create invite links according to their role.
- Clarified permanent deletion by identifying the exact category, operational group, or trip and requiring its current name only after opening the Danger Zone.
- Fixed group-name validation so valid names such as `Bus 2` remain neutral and duplicate or empty names show specific explanations.
- Made inactive and active attendance states coherent, prevents duplicate starts, and replaces Start with Open while attendance is active.
- Added realtime foreground attendance alerts, an in-app banner, and an optional local Android notification when Haajar is open and permission was already granted.
- Hid the broken remote push-registration setting for this Firebase-free beta. No FCM or Expo push token is required for foreground alerts.

## Required backend update

The hosted Supabase project includes migrations `20260812000100_hierarchical_group_admin_and_assignment.sql`, `20260812000200_unique_active_group_names.sql`, and `20260812000300_foreground_attendance_alerts.sql`.

## Beta status

Intended for a small closed group of Android testers.

## Installation

Download `Haajar-v0.9.0-beta.3.apk` from this prerelease. It uses Android versionCode `6` and the same release signing identity as beta.2, so it can be installed as an update.

Android may request permission to install apps from the browser or file manager because this beta is distributed outside Google Play.

## Notification behavior

Attendance-start alerts are reliable while Haajar is open and connected. The group screen updates through Supabase Realtime, an actionable banner appears, and Android can show a local notification if permission was previously granted. Without FCM, a local notification cannot wake an app that is closed or background-restricted.
