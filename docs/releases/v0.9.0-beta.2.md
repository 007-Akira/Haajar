# Haajar v0.9.0-beta.2

Second closed beta release of Haajar.

## Changes since beta.1

- Fixed attendance-start alerts so every active roster member receives an in-app notification, even without a registered push device.
- Retained attendance notifications in the app inbox for seven days.
- Preserved phone push delivery for all roster members, including organisers and super organisers, when they have an active registered device and notification permission.
- Fixed trip cards to display sequential numbers (`01`, `02`, `03`, and so on).
- Replaced native Android confirmation and status popups with Haajar's custom themed dialog across attendance, trip, group, registration, and edit flows.
- Added regression coverage for notification recipients, inbox retention, trip numbering, and themed dialogs.

## Required backend update

Apply Supabase migration `20260808000600_notification_recipients.sql` before testing attendance notifications. Keep the push-delivery Edge Function scheduler enabled for phone delivery.

## Beta status

Intended for a small closed group of Android testers.

## Installation

Download `Haajar-v0.9.0-beta.2.apk` from this prerelease. It uses Android versionCode `5` and the same release signing identity as beta.1, so it can be installed as an update.

Android may request permission to install apps from the browser or file manager because this beta is distributed outside Google Play.

## Audit summary

- TypeScript, ESLint, Prettier, and all 28 mobile tests pass.
- Expo dependency versions match the locally installed SDK compatibility map.
- No native React Native `Alert` usage remains in application source.
- The production dependency audit retains the previously documented Expo/Metro build-tooling advisories. npm's automatic remediation requires breaking framework changes, so that upgrade remains deferred until after this closed beta.

## Known issues

- Physical push delivery still depends on notification permission, a registered device, the deployed notification migration, and the scheduled push worker.
- Expo/Metro build-tooling dependency advisories remain pending a compatible framework upgrade.
